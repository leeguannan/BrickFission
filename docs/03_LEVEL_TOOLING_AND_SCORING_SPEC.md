# 自动化关卡工具链、可扩展 Schema 与难度评分引擎（Milestone 3）

> **模块路径**：`src/game/levels/`（纯 TS 核心）、`src/studio/`（Web 可视化工作台）
> **核心目标**：彻底解决人工手摆上千个微砖块效率低的问题，建立**“结构可扩展 + 自动化批量生产 + 物理盲测精准打分”**的工业化内容管线。

## 1. 可扩展关卡数据格式（`LevelSchema.ts`）

采用 **`元数据 + 调色板字典 + RLE 压缩网格`**，单关 1600 格压缩后仅约 `300~800 bytes`，500 关总体积 `< 300KB`。

```typescript
export interface TilePaletteEntry {
  symbol: string;       // 单字符编码，如 '.', 'R', 'G', 'S', '2', 'B'
  role: BrickRole;      // EMPTY | NORMAL | STEEL | BOMB | PRISM | CORE
  hp: number;           // 耐久度（NORMAL 可为 1, 2, 3...；STEEL 为 9999）
  color: string;        // 十六进制填充色，如 '#ef1d1d'
  dropTag?: string;     // 预留：击碎掉落（如 'skill_blue' | 'skill_orange' | 'buff_3choose1'）
}

export interface LevelMechanicsConfig {
  defaultBallSpeed?: number;
  initialSkills?: { multiLaunch: number; tripleSplit: number };
  // --- 预留 Step 2~4 扩展字段 ---
  rotationSpeedDegPerSec?: number; // 预留：如齿轮阵自转
  bossMode?: boolean;              // 预留：Boss 像素体
  roguePoolId?: string;            // 预留：三选一词条池
}

export interface LevelDefinition {
  version: 1;
  id: string;
  name: string;
  cols: number;          // 建议范围 28 ~ 48，默认 42
  rows: number;          // 建议范围 24 ~ 42，默认 36
  palette: Record<string, TilePaletteEntry>;
  /**
   * RLE 压缩格式，如 "42.|10S22R10S|..."
   * 行间用 '|' 分隔，单格前带数字表示重复次数（如 "10S" = 10个钢墙，"R" = 1个红砖）
   */
  rleGrid: string;
  difficultyScore?: DifficultyReport; // 由评分引擎自动写入
  mechanics?: LevelMechanicsConfig;
}
```

### 编解码规则要求
* `encodeRLE(grid)` 与 `decodeRLE(levelDef)` 必须严格无损可逆，并编写单元测试验证边界（如全空行、跨行不合并、数字 `>= 1` 解析）。

## 2. 三大自动化关卡生成器（`LevelGenerators.ts`）

### 生成器 A：文字 / PNG 像素图一键转关卡（`fromImageOrText`）
* **用途**：1 秒复刻截图 2 的“干”字关、或把任何图标/文字变成可玩关卡。
* **实现算法**：
  1. 接收灰度像素矩阵或离屏文字栅格化结果（支持模式：`POSITIVE` 文字本体为砖块 / `NEGATIVE` 背景铺满砖块、文字笔画镂空为通道，正好还原截图 2 效果！）。
  2. 按目标 `(cols, rows)` 下采样二值化（阈值可调）。
  3. 支持**“自动外框包边”**选项（如自动在四周加一圈 `STEEL` 灰墙，底部居中留出 `6~8` 格发球入口，复刻截图 3 效果）。

### 生成器 B：对称几何图腾生成器（`generateSymmetricTotem`）
* **用途**：批量生成类似截图 1 齿轮太阳阵、曼陀罗、蝶形等极具视觉美感的关卡。
* **实现算法**：
  1. 仅生成左上角 `1/4` 或 `1/8` 区域（结合极坐标环形半径掩码 + 径向辐条 + 中心空腔）。
  2. 通过 4 象限镜像复制，在图腾轮廓边缘自动镶嵌 `STEEL` 灰墙描边，并**强制确保底部中央至少有一条宽度 `>= 3` 格的“引流通道”直通中心空腔**，保证玩家能把球打进去挖洞！

### 生成器 C：迷宫挖洞通道生成器（`generateExcavationMaze`）
* **用途**：批量产出耐玩、结构多变的策略穿洞关。
* **实现算法**：
  1. 先用普通可碎砖块填满矩形区域（或分成类似截图 3 的多个矩形块矩阵）。
  2. 用随机有向掘进算法（Random Walk Carver）自底向上挖掘 `1~2` 条 `2~3` 格宽的曲折通道通往内部盲盒空腔。
  3. 依据难度参数，在部分壁垒下方嵌入一定比例的 `STEEL` 墙，迫使玩家必须通过角度反弹绕过钢墙进入上层。

## 3. 自动化难度打分引擎（`DifficultyScorer.ts`）

严禁只统计“砖块数量”作为难度！本引擎采用 **静态结构分析（40%）+ 无头物理盲测模拟（60%）** 给出 `0 ~ 100` 精准评分及废关拦截：

```typescript
export interface DifficultyReport {
  totalScore: number;           // 0 ~ 100 综合难度分
  tier: 'EASY' | 'MEDIUM' | 'HARD' | 'EXPERT';
  breakableCount: number;       // 可破坏砖块数
  steelOcclusionRatio: number;  // 钢墙遮挡比（位于可碎砖下方的钢墙占比）
  simBreakRate20s: number;      // 模拟前 20 秒平均清砖率 (0~1)
  hasDeadZoneWarning: boolean;  // 是否存在封闭死区（外部球完全无法触及的砖块）
}
```

### 评分核心逻辑
1. **死区连通性检测（BFS/Flood Fill）**：
   * 从挡板所在区域出发，按 `8` 邻域（但允许斜穿至少 `2` 格空隙或从可破坏砖块一路打通，**仅不可破坏的 `STEEL` 封闭围墙会阻断连通**）做连通性检查。
   * 如果存在被 `STEEL` 死死封住且没有任何开口的 `NORMAL` 砖块，立即标记 `hasDeadZoneWarning = true`（废关警告，禁止进入正式关卡库！）。
   * **默认发球线封死检测（M2 实测盲区，M3 必须实现）**：从默认发球位（挡板中心正上方、角度 0° 的垂直线，宽度至少覆盖球 AABB 跨越的 2 个网格列）向上追踪，若该通道在抵达首个可破坏砖之前被连续 `STEEL` 封死，同样按废关拦截，禁止入库。机理：`docs/01` §3.5 规定 `bouncesSinceBrick` 每次撞击挡板即清零，球一旦在「钢墙 ↔ 挡板中心」之间形成二点垂直弹跳腔，18 次死锁自救阈值永远无法累计，最小垂直分量保护只管水平腔体、残局软追踪又要求剩余砖块 ≤ 12，三者均不触发，回合永不收敛（M2 无头冒烟实测：12000 帧零 `BRICK_HIT`）。M2 的齿轮阵与框体绿砖门已通过几何开门（中轴通道、框体底边入口）规避，M3 校验器须在生产侧兜底，任何生成器或手工关卡都不得绕过。
2. **静态拓扑分（满分 40）**：
   * 基于总血量密度、`STEEL` 墙遮挡占比（`STEEL` 越靠下方遮挡越严密，分数越高）、底部入口最窄通道宽度计算。
3. **Headless 蒙特卡洛物理盲测（满分 60）**：
   * 直接实例化 `src/game/core/GameEngine`（无渲染器、无音频），模拟 **8 个典型开局角度**（如 `±15°, ±30°, ±45°, ±60°`），以 `FIXED_DT` 运行 `20` 秒虚拟时间（挡板开启简易自动追踪接球 AI 避免过早掉落）。
   * 统计所有角度下 20 秒内**平均消砖百分比 `simBreakRate20s`**：
     * 消砖率越快（如 `> 45%`），说明结构极易钻洞爆破，偏爽快解压关（难度分低）；
     * 消砖率越慢（如 `< 12%`），说明钢墙阻挡极强、必须精准找角度或依赖技能，偏硬核挑战关（难度分高）。
   * *性能指标*：单关 8 轮 × 20 秒物理模拟在 JS 中执行总耗时应控制在 **`< 150ms`**。

## 4. Web 端可视化关卡工作台（`src/studio/`）

在 Web 版中提供一个侧边/模态工具界面 **Level Studio**，供策划或开发者直接使用：
1. **绘图画布**：点击/拖拽绘制砖块，支持选色板（红砖/绿砖/钢墙/橡皮擦）、**一键开启左右镜像 / 四象限镜像**。
2. **一键自动生成面板**：
   * “汉字/文字成关”输入框（输入任意字符立即生成）；
   * “PNG 像素图上传导入”（读取图片像素自动转 RLE）；
   * “随机对称图腾 / 迷宫通道”一键抽卡。
3. **实时难度仪表盘**：画完或生成后点击“物理盲测打分”，立即展示 `totalScore`、难度评级、死区警告状态。
4. **一键试玩 & 导出 JSON**：点击“立即试玩”直接把当前编辑器关卡注入游戏引擎开打；满意后复制 JSON 追加到 `builtinLevels.ts`。

## 6. M3 落地实现与规格校准记录（Milestone 3 交付）

> 本节记录 M3 实现过程中对上文规格的**实测校准**与最终落地形态。涉及物理现实与字面规格冲突之处，均以"规格失配 + 实测数据"的方式显式留痕，不做静默偏离。

### 6.1 目录与职责

| 文件 | 职责 |
| --- | --- |
| `src/game/levels/LevelSchema.ts` | 调色板字典、Schema 校验、自有 RLE 编解码（保 `dropTag` 无损） |
| `src/game/levels/LevelGenerators.ts` | 三个生成器：二值图案、严格对称图腾、随机挖掘迷宫 |
| `src/game/levels/DifficultyScorer.ts` | BFS 死区检测、静态拓扑分、Headless 物理盲测（与 `GameEngine` 同源） |
| `src/game/levels/builtinLevelData.ts` | 20 关静态数据（由 `scripts/generate-builtin-levels.ts` 离线生成，**勿手工编辑**） |
| `src/game/levels/builtinLevels.ts` | 加载期校验 + 索引访问（`getBuiltinLevel` / `getBuiltinRuntimeConfig`） |
| `src/studio/` | Level Studio：`studioModel.ts`（纯逻辑）、`imageRasterize.ts`（Canvas 栅格化）、`StudioController.ts`（DOM 控制器） |

### 6.2 规格校准一：RLE 数字符号与 run 计数存在词法冲突

RLE 格式为 `[数字]符号`，数字是重复次数前缀；而 2/3/4 血砖若以单字符 `'2'/'3'/'4'` 编码，**计数省略（count=1）时裸数字符号会被解码器的数字扫描循环误吞为计数**，导致后续符号整体错位，且解码告警为空（静默错位，比显式报错更危险）。

处置：
* 调色板多血符号改为字母：`D`(2 血)、`E`(3 血)、`F`(4 血)；动态符号池只保留 `A-Z`/`a-z`。
* `encodeRLE` 增加防御：调色板符号为数字时直接抛错，提示改用字母符号。
* 修复**只在 levels 层**落地，`src/game/core/BrickGrid.ts` 的既有 RLE 实现未改动（core 运行时走 `cells` 路径，不触发其解码分支）。

### 6.3 规格校准二：盲测清砖率参考点按物理实测重标定

§3 写明"`> 45%` 为简单关、`< 12%` 为硬核关"。实测：42×38 关卡裸单球 20 秒仅能击碎个位数至十余块砖，清砖率被**关卡分母规模**压到 `≤ 2.6%`，字面阈值不可达。

处置：
* 盲测改用**标准技能玩家协议**（首发 + 2 次蓝标连发 + 第 30 帧 1 次橙标分裂，共 33 球），使样本覆盖真实开荒打法；
* 参考点重标定为 `EASY_RATE = 0.28`、`HARD_RATE = 0.05`，难度因子 `clamp((0.28 - rate) / 0.23, 0, 1)`；
* 实测清砖率带宽 `0.008 ~ 0.75`，20 关难度分成功散开 `13 ~ 93`，单关 8 轮盲测耗时峰值 `35~36ms`（预算 `< 150ms`，零超标）。
* 墙钟耗时与并发度相关：`node --test` 默认多文件并发执行，CPU 被抢占时同一用例的墙钟耗时可达 `273~336ms`。因此单测只断言 `withinSimBudget` 与实测耗时**自洽**，并用 `10×` 预算兜底性能回归；严格预算结论用 `npm run test:serial`（`--test-concurrency=1`，无竞争）复核，实测 `26~35ms`。

### 6.4 规格校准三：发球线封死检测的语义边界

§3.1 要求"默认发球线被连续 STEEL 封死则拦截"，但若按"任意双 STEEL 行即封死"实现，会把**顶部自动外框**（汉字关必有）误判为废关。实际语义细化为：自底向上扫描中央两列，遇到双 STEEL 行时——位于 `row 0` 判为顶部外框封顶（**不算封死**）；位于 `row > 0` 且其下方尚无任何可破坏砖可打时才判封死。

### 6.5 生成器的两条必要修正

* **图腾描边留底口**：`STEEL` 描边会把圆盘外缘闭成钢壳，内部砖块被 BFS 判为死区而整体清空（一度只剩 2 块砖）。修正为"朝挡板战场的收口面保留可破坏砖不转 STEEL"。
* **迷宫/图腾统一出口净化**：三个生成器出口统一调用 `sanitizeUnreachable`，清除 BFS 判定不可达的砖块，`STEEL` 保留。

### 6.6 内置 20 关的选关规则

离线扫描参数网格（图腾 48 组 + 迷宫 24 组 + 二值图案 15 组），按 §5 的三带配额等间距取样，保证难度分**单调不减**：`1~3` 新手带、`4~10` 钻洞带、`11~20` 高难带，且全部通过死区/封门校验与 `GameEngine` 盲测。重跑 `npx tsx scripts/generate-builtin-levels.ts` 可完整复现 `builtinLevelData.ts`。

### 6.7 规格校准四：消除「1 格钢墙暗袋」（2026-11-27 架构师拍板）

排查 20 关地图与机器人回归日志后确认：**第 1~10 关的图腾边缘生成了大量 1 格钢墙暗袋**（第 1 关仅 88 砖却在 900s 卡在 67/88），机器人与真人玩家都会在暗袋里垂直弹跳出不来。三处修正：

1. **可达性判定改严格 4 邻域**（`DifficultyScorer.computeReachable`）：原 8 邻域会把「两块 STEEL 对角夹出的 1 格缝」误判为通路 —— 球心直径 13px 根本钻不过去。斜穿一律不算通路。
2. **新手关关闭内部锯齿描边**（`LevelGenerators.generateSymmetricTotem` 的 `steelOutline`）：`applySteelOutline` 重写为「只给**外部连通空地**旁边的砖描边」，内部随机空洞不再被转成打不破的孤立钢刺。`markOutsideEmpty()` 从网格边界做 4 邻域 flood fill 标记外部空地。
3. **迷宫改用成段连续钢墙隔断**（`MazeOptions.steelLayout='bands'`）：旧版按 `steelRatio` 随机撒 STEEL 会在砖阵里制造 1 格宽钢壁口袋；新版每条带是 1 格宽的**连续竖直段**，带间距 ≥4 格（净距 ≥3 格），通道 / 盲盒空腔 / 默认发球线一律不落钢墙。

关卡数据随之重生成：难度带由 `1~3 / 4~10 / 11~20` 调整为 `1~5 / 6~10 / 11~20`（见 §5 修订说明），**后 10 关的千砖体量保持不变**（1048~1447 块）。

### 6.8 每关机器人打法标定表

实测**没有任何单一目标策略能通吃 20 关**，且策略偏好与关卡结构强相关（`deep` 通 {01,02,03,05,19,20}、`dense` 通 {01,02,04,05,07,18}、`breach` 通 {01,02,03,07,11,18,19}、`gap` 通 {01,03,04,18}、`slanted` 通 {01,03,05,12,18}、`onsight` 通 {01,02,04,18}）。「每球使用不同策略」实测**更差**（第 06 关 90.8% → 39.9%）—— 一个挡板只有一个位置，多个互相冲突的瞄准目标会让接球与出射角互相妥协。

因此把「这关该怎么打」固化为关卡元数据：`src/game/levels/builtinLevelStrategies.ts`（每关一组参数），由 `scripts/calibrate-level-strategies.ts` 离线标定生成 —— 对每关 × 每候选策略各跑一次 240s 虚拟时长的完整回归，取最快通关者。机器人运行时按关卡索引取用（`BF_BOT_STRATEGY=per_level`，默认）。

#### 2026-11-27 修订：四维标定与严格档实测

标定维度扩展为四项：**目标策略 × 残局切换阈值 × 目标球群规模 × 瞄准权重**，写入表的结构为 `{ strategy, endgameRatio, minGroupBalls?, aimWeight? }`。

三条实测结论（决定了表的形态）：

1. **残局阈值必须逐关标定**：固定 0.12 时第 12 关差 1 块、0.3 时第 19 关退回 96.3%，同一阈值无法同时服务两关。
2. **残局必须收缩球群到单球精度模式**：`maxCatches=1` 时单球出射角误差 P90 仅 0.25°（12 球时高达 29°）；第 19 关正是在此模式下通关（235.6s，1447/1447）。
3. **球群规模与瞄准权重是独立维度**：第 03 关在 `g=16, a=1` 下 69.3s 通关，而 `g=8, a=1.5` 需 103.9s。

严格档（240s、20/20）实测 **12/20 关通关**，最慢 223.3s、最低破砖率 74.1%；未通关关卡为 06/07/08/09/10/14/16/17。根因、证据与三个可选补救见 `docs/00` §6.4。
